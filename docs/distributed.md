# File workspace architecture

Jocki opens one app-level workspace and multiple ordinary folder vaults. The portable TypeScript core owns Automerge state, draft reconciliation, content contracts, indexing and protected sharing. Native filesystem and network services enter through explicit capabilities.

## Documents and persistence

The workspace is JSON outside every opened root, with an optional Automerge archive when history or sharing is enabled. Shared defaults and nullable overrides for every computer live in that document. Authorized computers can change defaults or another computer’s overrides. Local folder tokens resolve only through that device’s selected-folder capabilities; receiving settings grants no filesystem access.

Each vault contains ordinary Markdown, CSDB, JSON Canvas and arbitrary assets, plus optional sibling binary containers described in [Workspace files and companions](workspace-files.md). Each enabled file has one independent Automerge archive. Companions preserve stable application IDs; the device-local root index tracks paths and tombstones. Content type lives in optional resource metadata. A rename changes a path without combining the file’s history with other documents.

Markdown uses collaborative text. CSDB uses the reference parser and executor, with structured CRDT rows and fields and an ordinary CSDB text projection. Binary replacements retain conflicting values. Native snapshot comparison uses libgit2 to infer moves with edits; there is no filesystem-ID or exact-hash fallback. Browser/mobile hosts without a libgit2 binding do not infer unmatched external moves. Uncertain moves become independent files.

The core serializes writes. Save persists its recovery state, materialized file/resource pair and device-local baseline before acknowledging success. Content archives are retained only for enabled features. A failed materialization can be retried after restart. The baseline stores heads, hash, epoch and path so an external editor’s changes merge against the version it actually read. Filesystem watchers are notifications; reconciliation remains authoritative. Kernel leases prevent concurrent native writers to the same vault.

Editors and plugins hold private drafts until explicit Save. The shared editor service owns validation, will-save hooks, durable persistence, dirty-close decisions and lifecycle notifications. A draft preserves its original baseline during remote changes. Typing during disk I/O remains unsaved after the submitted snapshot completes. [File extensions](file-extensions.md) documents the separate extension contract.

## Protected sharing

`packages/core/repository.ts` uses pinned Automerge Repo, Keyhive and Subduction versions. Browser/mobile transport caches use the official IndexedDB adapter; desktop/headless use the official NodeFS adapter. The protocol cache and signing identity are local app data, separate from canonical vault documents. Browser initialization awaits the bundled Automerge Wasm module before opening documents.

Workspace, vault, folder and single-file shares have independent encrypted manifests and Keyhive groups. An administrator signs each share’s immutable scope contract; receivers pin that contract locally. A single-file share follows the file ID after a rename and never includes a replacement at its former path. Folder entries are confined to the selected destination. Whole-vault joins require an empty destination. Signed contracts identify the stable source unit. Local mount/file bindings route transport without becoming portable identities. Folder metadata uses its own authenticated document, while files keep independent content histories. Per-share routing baselines preserve local moves while an older manifest is being authorized; retired URLs cannot rebind a file. Semantic comparisons prevent equal manifest entries from generating new changes.

Whole-workspace groups include selected vault shares and future files. A newly enabled vault can inherit that group, while its recipient still chooses a local folder explicitly. Workspace settings can sync independently of the selected local vaults. Native document membership checks cover manifests, content and retention controls. An invitation identifies a document; its recipient’s contact card must receive a separate grant.

When a file leaves a shared folder, its old protected transport document is retired before publishing future edits. Remaining scopes receive a fresh protected URL while the application file ID and history remain intact. Old recipients retain data they already received; removing membership cannot erase their copies. Overlapping scopes do not widen the signed folder/file boundary.

History and sync are independent. History-off files and folders with no external participants discard old versions immediately, even when Sharing is enabled but has no grants. Shared file and folder archives use the same durable freeze, acknowledgement and generation checkpoint. A unit's descriptor keeps its protected transport/control references until agreement completes, so disabling sharing cannot prematurely remove its archive. Retention control messages continue while ordinary content sharing is blocked; private saved edits are never published just to finish cleanup. After every signed commit acknowledgement, each computer deletes the previous protected transport and drops unnecessary local archives. Folder-only changes advance the UI snapshot revision, including metadata writes, pruning and externally changed policies. Offline members delay pruning. Dirty drafts, unacknowledged edits and unresolved conflicts block it. Re-enabling sharing after completed cleanup reapplies saved private edits to the authenticated checkpoint baseline, preserving concurrent remote edits without reviving deleted history. Unrelated stale generations require explicit rejoin or an independent saved copy. Ordinary Automerge serialization is not history removal. Recovery is available only while history is enabled and uses the retained versions; recovering a deleted file creates a new identity without restoring old grants.

History tables provide Delete version and Reset history. Deleting a version removes that change's edits and replays the later deltas onto the preceding state. Reset keeps the current saved contents as one new creation version. File content and resource metadata are rewritten together; folder rewrites affect declarations without rolling back child file contents or access policy. Required data structures must remain valid, and validation fails before replacement if replay cannot produce a valid document.

`packages/core/vaults/history-rewrite.ts` provides reusable, deterministic `rewriteHistory` and `replayHistoryDelta` functions. They build a fresh Automerge DAG without mutating the input or retaining the deleted changes. Text and list edits rebase against the changed baseline; independent map fields replay separately. The file, folder and workspace services serialize and persist replacements. Shared rewrites use the same signed freeze/commit barrier as retention cleanup, including read-only participants; an editor can request a rewrite from the share administrator. Offline computers delay it. Drafts must be clean when freezing; typing after the freeze is rebased onto the replacement. Every participant checks the deterministic rewrite before adopting it, and old protected bytes are removed only after committed acknowledgements.

## Search, plugins and effects

Per-vault MiniSearch indexes are disposable derived data, rebuilt from visible files and declared extension extractors. Index persistence never changes source content. The registry defines shared MIME/content requirements rather than plugin-specific storage tables.

Extension manifests declare contributions before activation. Portable code runs in isolated worker hosts; editor webviews receive scoped draft ports. Core never interprets replicated content as commands. Installing code, enabling native capabilities and invoking commands are separate local decisions. Native entrypoint execution is not exposed by the browser host.

The headless application opens selected filesystem vaults through the same FileVault, workspace, retention and sharing services. Its optional HTTP server serves static UI and health checks. Web clients are independent replicas; HTTP access does not expose the server’s folders, shell or plugin runtime. See [Self hosting](self-hosting.md).

## Verification

`tests/file-vault.test.ts` covers durable drafts, crashes, external edits, renames, path reuse, CSDB field merging, history and deleted-file recovery. `tests/vault-sharing.test.ts` exercises real authenticated peers, inherited grants, concurrent additions, scope forgery, transport separation, folder exit and shared checkpoints. Retention tests cover freeze/ack failures and stale generations. Native tests cover libgit2, symlink containment and writer leases; the Node runtime test exercises actual filesystem watches and restart.

The file-vault and extension browser integrations exercise explicit Save, dirty close, editable indented tables, multiple vaults, persistence, signed packages and sandboxed hooks. Desktop development integration covers native selection, reload, pop-outs and Save/Discard/Cancel on quit. Headless CLI/container tests cover persistence and selected folders. Platform verification also builds the shared web UI, headless runtime, desktop renderer/main process and iOS/Android applications.
